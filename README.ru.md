# MZD Touch Installer

**Сенсорный Android Auto, сенсор во время движения и съёмный автозапуск для Mazda Connect 74.00.324 / 74.00.324A. Всё ставится и снимается одной флешкой.**

[English](README.md) · [Deutsch](README.de.md)

| | |
|---|---|
| Проверено в машине | Mazda Connect **74.00.324A** (EU, `cmu150_EU`) |
| Должно работать на | любой регион 74.00.324 / 74.00.324A (например, Северная Америка). Если блок отличается от проверенной сборки, установщик об этом говорит и спрашивает, прежде чем что-то менять. Сообщения о результате приветствуются. |
| Нужно | флешка (FAT32) и больше ничего: ни компьютера в машине, ни оригинальных файлов Mazda |

Здесь собраны два проекта сообщества. Их файлы включены **без изменений**, кроме одной настройки в `libpatch.conf` oem-aa-mod (Android Auto 1.5 вместо 1.6, см. [Android Auto 1.5 и беспроводные адаптеры](#android-auto-15-и-беспроводные-адаптеры)). Автозапуск написан для этого установщика:

| Часть | Проект | Автор | Лицензия |
|---|---|---|---|
| Сенсор в Android Auto | [oem-aa-mod](https://github.com/VitaliyKurokhtin/oem-aa-mod) 0.10.0 | [VitaliyKurokhtin](https://github.com/VitaliyKurokhtin) | AGPL-3.0 |
| Сенсор во время движения (меню Mazda Connect) | [TouchTune](https://github.com/Miatafy/TouchTune) 1.2.1 | [Miatafy](https://github.com/Miatafy) | GPL-3.0 |
| Автозапуск | этот установщик ([`xx74/`](stick/xx74)) | [caeptncrack](https://github.com/caeptncrack) | GPL-3.0-or-later |

Заслуга за первые две части принадлежит их авторам. Поставьте им звезду и поддержите оригиналы. Этот репозиторий добавляет:

- одну флешку и один диалог для всех трёх частей (установка, удаление, диагностика)
- строки сенсора из oem-aa-mod дописываются в **собственные** XML-файлы Android Auto машины, а не подменяют их, поэтому видеопараметры, которые получает Android Auto (и вместе с ними масштаб картинки), остаются заводскими; см. [XML Android Auto](#xml-android-auto)
- резервную копию оригинальных файлов **в машине** до первого изменения; удаление восстанавливает именно эти файлы, так что файл Mazda не нужно брать из интернета или с флешки
- защиту каждой записи: проверенный состав флешки, временная копия, проверка XML, атомарное переименование, чтение обратно, автоматический откат и один штатный SafeReboot Mazda в конце
- файл диагностики, который можно приложить к сообщению об ошибке

## Что вы получаете

**Сенсор в Android Auto** (oem-aa-mod, его выпускная конфигурация с выключенным Android Auto 1.6):

- сенсорный ввод в Android Auto на экране Mazda Connect
- подсказки поворота из Android Auto на проекционном дисплее, если он есть (стрелка, расстояние, название улицы)
- отключение звука ставит медиа телефона на паузу, включение звука продолжает воспроизведение
- Mazda Connect больше сам не запускает медиа Android Auto (запускайте воспроизведение из Android Auto или с телефона)
- к телефону по-прежнему Android Auto 1.5, как с завода, поэтому проводные телефоны и беспроводные адаптеры подключаются как раньше (см. [ниже](#android-auto-15-и-беспроводные-адаптеры))
- картинка Android Auto сохраняет видеопараметры самой машины (см. ниже)

Подробности каждой настройки — в [README oem-aa-mod](https://github.com/VitaliyKurokhtin/oem-aa-mod).

**Сенсор во время движения** (TouchTune): сенсорный экран Mazda Connect продолжает работать, когда машина едет (по умолчанию Mazda его блокирует, как только машина трогается).

**Автозапуск** (написан для этого установщика, см. `xx74/SOURCE.txt` на флешке): при каждом старте Mazda Connect запускает `/data_persist/dev/bin/autorun`, а тот выполняет все скрипты `*.autorun`, положенные в этот каталог. Установщик такой скрипт не привозит, поэтому хук ничего не делает, пока скрипт туда не положат. Он не запускает этот установщик с флешки, не читает команды из файла на флешке и не ставит `adb`. **Remove** снимает хук и восстанавливает исходные скрипты запуска из копии, сделанной в машине.

> **Безопасность и закон.** Сенсорный экран за рулём отвлекает. Пользуйтесь им только когда это безопасно и разрешено там, где вы едете (в Германии, например, § 23 (1a) StVO ограничивает управление устройствами во время движения). Ответственность остаётся на вас. Лучше, если экраном пользуется пассажир.

## Использование

1. **Скачать.** Откройте [последний релиз](../../releases/latest) и скачайте **`mzd-touch-installer-<version>.zip`** в разделе *Assets*. Не «Source code»: это исходный текст для разработчиков. На компьютере ничего устанавливать и собирать не нужно.
2. **Подготовить флешку.** Пустая флешка до 32 ГБ, файловая система **FAT32** (Windows: правый щелчок по флешке → *Форматировать…* → *FAT32*).
   - **Windows:** правый щелчок по ZIP → *Извлечь все…* → *Обзор…* → выбрать флешку → *Извлечь*. Или распаковать куда угодно, открыть папку, выделить всё внутри (Ctrl+A) и перетащить на флешку. Извлеките флешку, прежде чем вытаскивать её.
   - **macOS:** дважды щёлкните ZIP, откройте новую папку, выделите всё внутри (Cmd+A) и перетащите на флешку. Затем откройте *Терминал* и выполните `dot_clean -m /Volumes/<STICK>` (Finder добавляет скрытые файлы `._`, из‑за которых машина может не запустить флешку). Извлеките флешку.
   - **Проверка:** на флешке сразу видны `run.sh`, `README.txt`, `STICK.ID` и папки `aa-mod`, `lib`, `payload`, `touchtune` и `xx74`, а не внутри ещё одной папки. Больше на флешке ничего нет.
3. **В машине.** Надёжнее при работающем двигателе (блок не должен потерять питание во время записи). Дождитесь, пока Mazda Connect полностью запустится. Вставьте флешку в USB-разъём центральной консоли. Через несколько секунд диалог покажет текущее состояние:

   | Состояние | Кнопки |
   |---|---|
   | ничего не установлено | **Install** · Diagnosis · Cancel |
   | установлены все три части | **Remove all** · Diagnosis · Cancel |
   | установлена часть | **Install** · Remove · Cancel |
   | установлена более старая версия сенсора Android Auto | **Update** · Remove all (или Remove) · Cancel, см. [Обновление с 1.0.0](#обновление-с-100) |

4. Выберите **Install**. Откроется подтверждение: несколько строк о том, что произойдёт. Нажмите **Start** (**Back** возвращает к начальному диалогу). Так сначала спрашивает каждая кнопка начального диалога.
5. Пока идёт работа, на экране написано *Do not pull the stick*. Вынимайте флешку только когда экран сам это скажет: *Remove the USB* перед перезапуском или *You can pull the stick now*, если запуск закончился без перезапуска. Mazda Connect перезапускается сам (или спрашивает *Restart now*).
6. После перезапуска подключите Android Auto и нажмите на экран.

Если блок не та европейская сборка, на которой это проверяли, установщик так и пишет («differs from the build this installer was tested on») и спрашивает, продолжать ли. **Cancel** ничего не меняет.

## Удаление

Вставьте ту же флешку снова, выберите **Remove all** и подтвердите **Start**. Сенсор Android Auto и автозапуск восстанавливаются из копий, сделанных в вашей машине, байт в байт; TouchTune восстанавливает свою копию. В конце Mazda Connect перезапускается. Оригинальные файлы Mazda для этого не нужны.

После официального обновления ПО Mazda изменения пропадают, но шимы в `/data_persist` остаются. Запустите флешку снова: установщик заметит обновление, сделает новую копию и поставит всё заново.

## Обновление с 1.0.0

Положите новый релиз на флешку, как в [Использовании](#использование), шаг 2 (проще всего пустая флешка; папку `backup-aa-touch-*` со старой флешки сохраните отдельно), и вставьте её. Начальный диалог показывает *Android Auto touch: older version installed* и предлагает **Update**. Обновление идёт на месте:

- используется копия, которую первая установка сделала в машине (новой копии нет: заводские файлы остаются эталоном)
- конфигурация служб заново собирается из этой копии уже для Android Auto 1.5, шим `aap_service` от oem-aa-mod отодвигается в сторону, ставится новый `libpatch.conf`
- результат проверяется так же, как при новой установке; при ошибке всё откатывается к вашим исходным файлам
- если TouchTune ещё не установлен, он ставится в том же запуске

В конце Mazda Connect перезапускается. Установки ранних тестовых сборок, которые копировали XML-файлы oem-aa-mod, распознаются и обновляются так же: XML заново собираются из файлов вашей машины. **Remove both** работает и на старой установке и восстанавливает исходные файлы байт в байт; сначала обновляться не нужно. Состояние, которое установщик не может отнести к одной из своих версий, показывается как *partially installed*, и **Install** чинит его той же копией.

## Android Auto 1.5 и беспроводные адаптеры

В выпускном `libpatch.conf` oem-aa-mod стоит `use_protocol_v1_6 = true`: тогда машина предлагает телефону Android Auto 1.6, и телефон отдаёт полные данные навигации (включая полосы) для проекционного дисплея. По беспроводному соединению (беспроводной адаптер Android Auto в USB-разъёме) телефон, который видит 1.6, пропускает запрос сопряжения Bluetooth, которого Mazda Connect ждёт, прежде чем показать Android Auto. oem-aa-mod перекрывает это для адаптеров, чьё имя USB он узнаёт (`bt_pairing_bypass_all_devices` распространяет это на все устройства); с остальными адаптерами картинки нет, и обход зависит от тайминга.

Поэтому этот установщик привозит `libpatch.conf` с этой одной строкой `use_protocol_v1_6 = false` (значение по умолчанию у автора) и не загружает шим `aap_service` от oem-aa-mod, который действует только при 1.6. Машина предлагает Android Auto 1.5, как с завода, так что проводные телефоны и беспроводные адаптеры подключаются как всегда. Сенсор, пауза телефона по отключению звука и остальные настройки не меняются; на проекционном дисплее остаются стрелка поворота, расстояние и название улицы, подсказки полос требуют 1.6. Все остальные строки `libpatch.conf` — байт в байт выпускной файл (то же написано в `aa-mod/SOURCE.txt` на флешке). Установщик 1.0.0 ещё использовал выпускную настройку; см. [Обновление с 1.0.0](#обновление-с-100).

## XML Android Auto

oem-aa-mod привозит свои копии `/etc/aap_system_attributes.xml` и `aap_system_attributes_UCP.xml`. Кроме строк сенсора они переносят несколько видеопараметров в блок, который `aap_service` отправляет телефону (`par`, `fps`, `decoder_additional_depth`), и добавляют `real_density`. В заводском файле эти значения лежат там, откуда `aap_service` их не читает, поэтому с подменённым файлом телефон получает другие видеопараметры, и Android Auto может масштабироваться иначе, чем с завода.

Этот установщик оставляет два файла вашей машины и добавляет только то, что oem-aa-mod добавляет для своих функций:

- запись `<touch_screen>` в начале `<input_devices>` (`use_internally` true в основном файле, false в `_UCP`, как у oem-aa-mod)
- клавиша `AAP_KEYCODE_MEDIA_PAUSE` (отключение звука ставит телефон на паузу)
- у навигации `subscribe TRUE` и `<cluster_type>ENUM</cluster_type>` (подсказки на проекционном дисплее)

Все остальные строки остаются байт в байт как с завода, включая `<display>` и `<video>`. Перед записью установщик это проверяет: если убрать добавленные строки, должен получиться точно ваш исходный файл. Если у файла не тот состав, сенсор Android Auto не ставится, а TouchTune предлагается отдельно. На проверенной европейской сборке результат совпадает с файлом oem-aa-mod, кроме видео-блока. Два XML-файла oem-aa-mod остаются на флешке: они проверены, но не устанавливаются.

## Что установщик проверяет, прежде чем что-то менять

- каждый файл на флешке по `PAYLOAD.SHA256` (повреждённая или изменённая флешка отклоняется)
- версию прошивки (74.00.324 или 74.00.324A, любой регион; всё остальное отклоняется, и на флешку пишется файл диагностики)
- что нужные компоненты есть и совпадают ли они с проверенной сборкой (если нет, вас спрашивают)
- что Android Auto не менял другой установщик (файлы `.orig`, чужие строки `LD_PRELOAD`). Если менял, эта часть не трогается, и предлагается поставить остальные части отдельно
- что файл Common.js, который правит TouchTune, — известный (TouchTune проверяет это и сам). Если нет, флешка предлагает только сенсор Android Auto

Путь записи для каждого файла: копия в машине (пишется один раз и проверяется) → временная копия рядом с целью → проверка XML → атомарное переименование → чтение обратно. Любая ошибка откатывает к записанному состоянию; watchdog и корневая файловая система только для чтения возвращаются на место; затем запрашивается штатный SafeReboot Mazda (не простой reboot). TouchTune запускается своим неизменённым процессом с чистым окружением и только после того, как часть Android Auto закончена.

## Файлы, которые пишет флешка

| Файл | Содержимое |
|---|---|
| `mzd-usb.log` | журнал каждого запуска |
| `diag-*.txt` | пишет **Diagnosis**: версии, хеши файлов, состояние частей. Без содержимого файлов Mazda и без личных данных, так что файл можно приложить к issue |

## Если что-то не так

- **Диалог не появляется.** Проверьте: FAT32, файлы на верхнем уровне (проверка в шаге 2), на флешке нет посторонних файлов, не воткнуто другое USB-устройство, на macOS удалены файлы `._`. Попробуйте другой USB-разъём. Подождите до минуты после того, как Mazda Connect запустился.
- **Windows пишет, что имя файла слишком длинное.** Распаковывайте прямо на флешку (шаг 2) или в короткую папку вроде `C:\stick`. Одно имя файла на флешке длиной 184 символа, и глубокие папки, например некоторые пути OneDrive, его не вмещают.
- **«Unsupported firmware».** Поддерживаются только 74.00.324 и 74.00.324A. На флешке будет файл `diag-*.txt`.
- **«Another installer already modified Android Auto».** Снимите ту модификацию тем установщиком, который её поставил, затем запустите эту флешку снова.
- **«The files on the stick are damaged».** Скопируйте содержимое ZIP на флешку ещё раз (или возьмите другую флешку).
- **Что-то ещё.** Откройте issue и приложите `mzd-usb.log`, самый новый `diag-*.txt` и `touchtune/touchtune.log`. Папки `backup-aa-touch-*` **не** прикладывайте.

Для опытных: файл `ACTION.txt` на верхнем уровне флешки выбирает действие без начального диалога: `install`, `uninstall`, `diagnose`, `status` (только журнал) или `touchtune` (собственное меню TouchTune). Изменения всё равно подтверждаются на экране. Удалите файл, чтобы снова получить диалог.

## Собрать флешку самому

Для обычного использования это не нужно: ZIP из релиза — уже готовая флешка. Сборка у себя требует Python 3.8 или новее и больше ничего.

```bash
python3 tools/build_stick.py build --download
```

Команда скачивает два закреплённых выпуска с GitHub, проверяет каждый файл по закреплённому SHA-256, собирает `dist/stick/` и `dist/mzd-touch-installer-<version>.zip` и проверяет результат так же, как это делает машина. С `--target E:\` (Windows) или `--target /Volumes/STICK` она ещё и записывает флешку; цель должна быть пустой или уже содержать этот установщик (его журналы, диагностики и папки `backup-aa-touch-*` сохраняются). Уже скачанные файлы можно передать через `--aa-mod-zip`, `--touchtune-zip`, `--aa-mod-license` и `--aa-mod-notice`.

Закреплённые исходные файлы:

| Файл | SHA-256 |
|---|---|
| [oem-aa-mod-0.10.0.zip](https://github.com/VitaliyKurokhtin/oem-aa-mod/releases/tag/0.10.0) | `ba7a0c285269a87e8a199e38517de05da749a67df7ca016abb6d15e65112dc6a` |
| [TouchTune-1.2.1.zip](https://github.com/Miatafy/TouchTune/releases/tag/v1.2.1) | `3397a541aacebb1c0a4476c12eeb3479a643990ba67521745c7de47ad072dc68` |

## Тесты

```bash
sh tests/run-tests.sh
```

Набор запускается на любой оболочке POSIX (Git Bash, Linux, macOS, BusyBox ash в Docker) на поддельном дереве файлов Mazda Connect: установка, удаление, починка, частичные состояния, обновление на месте со старых версий, все подставленные ошибки записи и их откат, диалоги, другие регионы с неизвестными двоичными файлами, удаление байт в байт и правила приватности диагностики. Если в `downloads/` лежат ZIP авторов, набор прогоняет и настоящую флешку (а в git-копии с тегом `v1.0.0` ещё пересобирает флешку 1.0.0 и обновляет её установку на месте). С `MZD_TEST_REAL_ROOTFS=<дамп корневой файловой системы 74.00.324A>` настоящий TouchTune правит и восстанавливает настоящий Common.js.

